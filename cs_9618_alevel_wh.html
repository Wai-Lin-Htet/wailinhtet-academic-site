      1

      Information representation and multimedia

      Binary, denary, hexadecimal and BCD; two's complement; bitmaps, vectors and sound; compression.

      What you must be able to do

      • 1.1 Data representation — use binary, denary and hexadecimal bases and Binary Coded Decimal (BCD); represent positive and negative integers with one's and two's complement; convert between bases; add and subtract binary numbers and explain overflow; describe where BCD and hexadecimal are used in practice; represent character data with ASCII, extended ASCII and Unicode.
      • 1.2 Multimedia — explain how bitmap images are encoded (pixel, file header, image resolution, screen resolution, colour depth / bit depth) and estimate bitmap file sizes; explain how changing resolution or colour depth changes quality and file size; explain how vector graphics are encoded (drawing object, property, drawing list) and justify bitmap vs vector for a task; explain how sound is sampled and encoded and how sampling rate and resolution affect quality and file size.
      • 1.3 Compression — explain why compression is needed; compare lossy and lossless compression and justify a choice; explain how text, bitmap, vector and sound files are compressed, including run-length encoding (RLE).

      1.1Number systems and negative numbers

      Computers store everything as patterns of 0s and 1s. Denary is base 10, binary is base 2 and hexadecimal is base 16. Hexadecimal is a shorthand for binary: each hex digit stands for exactly four bits, which is why memory addresses and colour codes are usually written in hex. BCD is different again — each denary digit is stored as its own four-bit group, which is why BCD is used in displays and financial systems where exact decimal digits matter.

      Negative integers are normally stored in two's complement: to find the two's complement of a positive number, invert every bit and add 1. In 8 bits, +5 is 00000101, so −5 is 11111011. The big advantage is that the same addition circuit works for positive and negative numbers. Overflow happens when a result needs more bits than are available — for example, adding two large positive 8-bit numbers and getting a result that looks negative.

      Characters are stored as numbers too. ASCII uses 7 bits (128 characters: letters, digits, punctuation and control codes), extended ASCII uses 8 bits (256 characters), and Unicode uses 16 or more bits so it can represent almost every writing system in the world. You are not expected to memorise any particular character codes — but you must know which set to use and why.

      1.2Bitmaps, vectors and sound

      A bitmap image is a grid of pixels. Its file size depends on three things: the number of pixels (image resolution) and the number of bits used for each pixel (colour depth). A useful formula to learn is:

      File size

      Bitmap file size (bits) = image width in pixels × image height in pixels × colour depth in bits. Divide by 8 for bytes. Raising the resolution or the colour depth makes the picture sharper but the file bigger.

      A vector graphic is not a grid at all — it is a list of drawing objects (lines, curves, shapes) with properties such as position, size, fill colour and line thickness. Vectors can be scaled to any size without losing quality, so they suit logos and diagrams; bitmaps suit photographs, where every pixel can be a different colour.

      Sound is analogue, so it must be sampled: the sound wave is measured at regular intervals (the sampling rate, in samples per second) and each measurement is stored to a fixed precision (the sampling resolution, in bits). A higher sampling rate captures higher frequencies and a higher resolution captures quieter and louder detail — both make the file bigger. CD-quality sound is sampled 44,100 times per second at 16 bits.

      1.3Compression

      Lossless compression throws away nothing: the original file can be rebuilt exactly. Lossy compression throws away detail the eye or ear is unlikely to notice, so the file is much smaller but the original can never be recovered. Use lossless for text and data, and lossy for photographs, music and video where a little lost detail does not matter.

      Run-length encoding (RLE) is the simplest lossless method: a run of identical values is stored as one value plus a count. The string AAAAABBBCC becomes 5A 3B 2C. RLE works well on images with large flat areas of one colour and badly on photographs, where neighbouring pixels are almost never identical.

      Worked example — two's complement and a bitmap file size

      Worked example

      (a) Write −23 as an 8-bit two's complement number. 23 in binary is 00010111. Invert the bits: 11101000. Add 1: 11101001. So −23 = 11101001. Check: the leftmost bit is 1, which marks a negative number.

      (b) A bitmap is 800 × 600 pixels with a colour depth of 24 bits. File size = 800 × 600 × 24 = 11,520,000 bits = 1,440,000 bytes (÷ 8), about 1.4 MB before any compression or file header.

      Try it — denary, binary and hex converter

      Type in any box and the other two follow. This is the same conversion the exam asks for, up to 8 bits.

      Exam tips
      • Always show your working for conversions and binary arithmetic — method marks are available even if the final answer is wrong.
      • For overflow, state the range first: an 8-bit two's complement number can hold −128 to +127. A result outside that range overflows.
      • When a question asks you to justify bitmap vs vector, give the reason (scaling, photographic detail, editing) — not just the name.
      • Do not memorise character codes; know what ASCII, extended ASCII and Unicode are for and how many bits each uses.

      2

      Communication

      LANs and WANs, client-server and peer-to-peer, topologies, cloud computing, media and hardware, IP addressing.

      What you must be able to do

      • 2.1 Networks including the internet — explain the purpose and benefits of networking devices; describe LANs and WANs; compare the client-server and peer-to-peer models and justify a choice; explain thin-client and thick-client; describe bus, star, mesh and hybrid topologies and how packets travel in each; explain cloud computing (public and private clouds) and its benefits and drawbacks; compare wired and wireless networks and describe copper, fibre-optic, radio waves, microwaves and satellites; describe LAN hardware (switch, server, NIC, WNIC, WAP, cables, bridge, repeater); explain the role of a router; explain Ethernet and CSMA/CD; explain bit streaming (real-time and on-demand) and the effect of bit rate; distinguish the World Wide Web from the internet and describe the hardware that supports it; explain IP addressing (IPv4 and IPv6), DNS and MAC addresses.

      2.1Networks and models

      A LAN (local area network) covers a small area such as a school or office, is fast, and is usually owned by one organisation. A WAN (wide area network) covers a large area — the internet is the largest WAN — and is slower and owned by many organisations. In a client-server network, a central server provides services and controls security; in a peer-to-peer network, every computer is equal and shares files directly with the others. Client-server suits a school (central backups, one login, controlled access); peer-to-peer suits a small home network (cheap, no server to maintain).

      A thin client does almost no processing itself — it relies on the server for programs and storage. A thick client has its own processor, memory and storage and can work on its own. Thin clients are cheap and easy to manage centrally; thick clients keep working if the network fails.

      2.1Topologies and media

      TopologyHow it worksStrengthWeakness
      BusAll computers share one cable; data travels along the bus to its destination.Cheap and simple to set up.If the main cable fails, the whole network fails; collisions slow it down.
      StarEvery computer connects to a central switch or hub.One cable failing affects only one computer; easy to add computers.If the central switch fails, the whole network fails.
      MeshComputers connect to several others, so there are many routes.Very reliable — data can take another route if one link fails.Expensive: lots of cables and connections.
      HybridA mix of two or more topologies, e.g. star networks joined by a bus backbone.Combines the strengths of each part.Complex and expensive to design and manage.

      Data travels as packets. Wired media include copper cable (cheap, but signals weaken over distance and suffer interference) and fibre-optic cable (light pulses, very fast, immune to interference, but expensive to install). Wireless media include radio waves (WiFi), microwaves and satellites (good for remote areas, but slower and affected by weather and interference).

      2.1Hardware, addressing and the internet

      Key LAN hardware: a switch connects computers in a LAN and sends each packet only to its destination; a NIC (network interface card) connects a computer to the network and holds its MAC address; a WAP (wireless access point) lets wireless devices join a wired network; a bridge joins two similar networks; a repeater boosts a weakening signal. A router connects different networks together — it reads the destination IP address of each packet and forwards it towards the next network on its journey.

      Every device on a network has a MAC address (a permanent hardware address built into the NIC) and an IP address (a logical address that can change). IPv4 addresses are 32 bits written as four denary numbers (for example 192.168.1.10); IPv6 addresses are 128 bits written in hexadecimal, introduced because IPv4 addresses are running out. DNS (Domain Name System) translates human-readable names such as wailinhtet.com into IP addresses.

      Ethernet is the standard way computers share a cable. To avoid collisions, it uses CSMA/CD: a computer listens to check the cable is free, sends its data, and if two computers send at the same time (a collision) both stop, wait a random time and try again. Bit streaming sends audio or video as a continuous stream — real-time (live, cannot be paused) or on-demand (stored, can be paused). A higher bit rate means better quality but needs a faster connection.

      Finally, the internet is the network of networks; the World Wide Web is a service that runs on it (web pages linked by hyperlinks). Cloud computing means using storage and software on remote servers over the internet: a public cloud is shared by many customers, a private cloud is used by one organisation only. Cloud computing cuts the cost of buying and maintaining hardware, but it needs a reliable internet connection and raises questions about who controls your data.

      Worked example — choosing a topology and a model

      Worked example

      Question: A school has 200 computers in 8 classrooms and wants central control of logins, files and printing. Recommend a topology and a network model, giving reasons.

      Answer: Use a star topology in each classroom, with the classroom switches joined into a hybrid network, and a client-server model. Reasons: in a star, one faulty cable affects only one computer, so a fault does not stop a whole class; the server gives one login per student, central backups and controlled printing; and new computers are easy to add to a star. A bus would be a poor choice because one cable fault would stop a whole classroom, and peer-to-peer would give no central control over 200 users.

      Exam tips
      • Questions that ask you to "justify" a choice always want the reason, not just the name — link the feature of the topology or model to the situation in the question.
      • Do not confuse MAC and IP addresses: MAC is fixed hardware, IP is logical and can change; DNS links a name to an IP address.
      • For CSMA/CD, remember the order: listen, send, detect a collision, stop, wait a random time, resend.
      • Cloud computing questions often ask for a benefit and a drawback — give one of each.

      3

      Hardware

      Input, output and storage devices; RAM and ROM; logic gates, truth tables and circuits.

      What you must be able to do

      • 3.1 Computers and their components — describe input and output devices and sensors; explain RAM (SRAM vs DRAM) and ROM (PROM, EPROM, EEPROM); describe secondary storage (magnetic, optical, solid state) and compare them.
      • 3.2 Logic gates and logic circuits — describe the six standard gates (NOT, AND, OR, NAND, NOR, XOR); construct truth tables and Boolean expressions from a problem; draw and interpret logic circuits (examination circuits use at most three inputs and one output).

      3.1Memory and storage

      RAM is volatile working memory: its contents are lost when the power is off. SRAM (static RAM) uses flip-flops, is fast and expensive, and is used for cache memory. DRAM (dynamic RAM) stores each bit as a charge in a capacitor, is slower and cheaper, and must be refreshed regularly — it is the main memory of a computer. ROM is non-volatile and holds the start-up instructions: PROM can be written once, EPROM can be erased with ultraviolet light and rewritten, and EEPROM can be erased electrically.

      Secondary storage keeps data when the power is off. Magnetic storage (hard disk drives) is cheap with a large capacity but has moving parts and is relatively slow. Optical storage (CD, DVD, Blu-ray) is cheap and portable but holds less and is slower to write. Solid-state storage (SSD, USB flash, NAND flash) has no moving parts, is fast and silent, but costs more per gigabyte and wears out after many write cycles.

      3.2Logic gates

      Each gate takes binary inputs and produces one binary output. The six gates you must know are:

      ABNOT AA AND BA OR BA NAND BA NOR BA XOR B
      00100110
      01101101
      10001101
      11011000

      In words: AND is 1 only when both inputs are 1; OR is 1 when at least one input is 1; XOR is 1 when the inputs are different; NAND and NOR are AND and OR followed by NOT. A Boolean expression describes a circuit in symbols, for example X = (A AND B) OR C. To build a truth table, work out the intermediate columns first (for example A AND B), then combine them for X — never try to jump straight to the final column.

      Try it — logic gates

      Tap A and B and watch every gate output change.

      Worked example — truth table from a circuit

      Worked example

      Question: A circuit has X = (A AND B) OR NOT C. Complete the truth table row where A = 1, B = 0, C = 1.

      Answer: Work column by column. A AND B = 1 AND 0 = 0. NOT C = NOT 1 = 0. Then X = 0 OR 0 = 0. So for A = 1, B = 0, C = 1, X = 0. Building the full table the same way (8 rows for three inputs) gives X = 1 only when A AND B is 1, or C is 0.

      Exam tips
      • Write out intermediate columns in truth tables — they earn method marks and stop careless errors.
      • Read the question's gate count: examination circuits have at most three inputs and one output, so a truth table has at most eight rows.
      • XOR is the gate students mix up most: it is 1 when the inputs are different, 0 when they are the same.
      • When asked to draw a circuit, label every input and the output, and keep the gates in the same order as the expression.

      4

      Processor fundamentals

      Von Neumann architecture, the fetch-decode-execute cycle, registers, assembly language and bit manipulation.

      What you must be able to do

      • 4.1 Central Processing Unit (CPU) architecture — describe the Von Neumann architecture (ALU, control unit, clock, address/data/control buses); explain the role of the registers PC, MAR, MDR, CIR, ACC and the status register; describe the fetch-decode-execute cycle and the role of interrupts and interrupt service routines.
      • 4.2 Assembly language — compare machine code and assembly language; explain mnemonics, op-code and operand; explain immediate, direct, indirect, indexed and relative addressing; trace and write assembly routines for the Cambridge instruction set.
      • 4.3 Bit manipulation — use AND, OR and XOR with masks to test, set, clear and invert individual bits.

      4.1The Von Neumann architecture and the FDE cycle

      Almost every computer follows the Von Neumann architecture: one memory holds both program instructions and data, and a central processor fetches instructions from memory one at a time and executes them. The processor has an ALU (arithmetic logic unit, which does calculations and comparisons), a control unit (which directs the whole process), a clock (which sends regular pulses to time every step) and three buses: the address bus (one-way: processor to memory, carrying the address wanted), the data bus (two-way: carrying the data or instruction itself) and the control bus (carrying timing and control signals).

      RegisterRole
      PC (program counter)Holds the address of the next instruction to be fetched.
      MAR (memory address register)Holds the address of the memory location being read from or written to.
      MDR (memory data register)Holds the data or instruction that has just been read from, or is about to be written to, memory.
      CIR (current instruction register)Holds the instruction currently being decoded and executed.
      ACC (accumulator)Holds the result of a calculation while it is being worked on.
      Status registerHolds flags, for example whether the last result was zero or negative.

      The fetch-decode-execute cycle repeats for every instruction: fetch — copy the instruction at the address in the PC into the CIR (and increase the PC); decode — the control unit works out what the instruction means; execute — carry it out, which may move data or change the PC. An interrupt is a signal that makes the processor stop what it is doing, save its place, run an interrupt service routine (for example to handle a key press or a printer finishing), and then return to the saved place.

      4.2Assembly language and addressing modes

      Machine code is binary — the only language the processor understands directly. Assembly language is the same thing written with readable mnemonics: each instruction has an op-code (what to do, such as ADD or LDM) and an operand (the data or address to work on). An assembler translates assembly language into machine code.

      Addressing modeWhat the operand meansExample
      ImmediateThe operand is the value itself.LDM #25 loads the value 25.
      DirectThe operand is the address of the value.LDM 25 loads the value stored at address 25.
      IndirectThe operand is the address of an address: the value at that address is itself an address.LDM (25) loads the value at the address stored at address 25.
      IndexedThe operand address is added to the index register (IX).LDM 25, IX loads the value at address 25 + IX.
      RelativeThe operand is added to the PC — used for jumps.JMP +4 jumps four instructions ahead.

      4.3Bit manipulation with masks

      A mask is a pattern of bits used with AND, OR or XOR to change selected bits and leave the rest alone: AND with 0 clears a bit (and with 1 leaves it unchanged), so AND tests or clears bits; OR with 1 sets a bit; XOR with 1 inverts (toggles) a bit. For example, to set bit 2 of the register value 00001000, OR it with the mask 00000100 to get 00001100. To test whether bit 3 is set, AND the value with 00001000 and check whether the result is zero.

      Worked example — trace an assembly routine

      Worked example 
      LDM #0      ; load 0 into the accumulator
STO 50      ; store the accumulator at address 50
LDM 51      ; load the value at address 51
ADD #5      ; add 5
STO 52      ; store the result at address 52
END

      If memory location 51 holds 20, the trace is: ACC = 0, then address 50 holds 0; ACC = 20, then 20 + 5 = 25; address 52 holds 25. The routine copies 0 to address 50 and stores 25 (the value at 51, plus 5) at address 52. When tracing, write one row per instruction showing the ACC and any memory locations that change.

      Exam tips
      • Trace tables are the safest way to answer FDE and assembly questions — one row per step, one column per register.
      • Learn the register names and their jobs exactly: examiners ask "what is the role of the MAR?" as a one- or two-mark question.
      • Do not confuse addressing modes: immediate means the value is in the instruction; direct means the address is in the instruction.
      • For masks, remember: AND clears, OR sets, XOR flips — and always show the mask you used.

      5

      System software

      Operating systems, utility software, assemblers, compilers and interpreters.

      What you must be able to do

      • 5.1 Operating systems — explain the functions of an operating system (process, memory, file, device management and user security); describe utility software (disk defragmenter, backup utility, compression tools, file manager).
      • 5.2 Language translators — explain how a two-pass assembler works; compare compilers and interpreters, including their advantages, execution overhead, the debugging cycle and intermediate bytecodes.

      5.1What an operating system does

      The operating system is the software that manages the computer so that programs can run. Its main jobs are: process management (deciding which program gets the processor and for how long), memory management (giving each program the memory it needs and protecting programs from each other), file management (organising files and folders), device management (talking to printers, disks and other hardware through drivers) and user security (logins, passwords and access rights). Utility software helps maintain the system: a disk defragmenter gathers the scattered pieces of files back together so the disk reads faster, a backup utility copies files so they can be restored, and a compression tool shrinks files for storage or sending.

      5.2Translators: assemblers, compilers, interpreters

      What it doesStrengthWeakness
      AssemblerTranslates assembly language into machine code. A two-pass assembler reads the program twice: the first pass records the addresses of labels, the second pass produces the machine code — this is how it resolves forward references to labels that appear later in the program.Produces fast, small machine code.Assembly language is slow to write and hard to read.
      CompilerTranslates the whole high-level program into machine code (or bytecode) in one go, before it runs.The finished program runs fast; errors are reported together so they can be fixed before running.Must recompile the whole program after any change; the compiled code only runs on one type of processor.
      InterpreterTranslates and runs the program one line at a time, while it runs.Easy to test and debug — you can stop, fix and continue; the same program runs on any computer with an interpreter.Runs more slowly, because translation happens every time; an error stops the program part-way through.

      Some languages compile to bytecode — an intermediate code that runs on a virtual machine (for example Java bytecode on the JVM). This gives a middle ground: the program is compiled once, but the bytecode runs on any computer that has the virtual machine.

      Worked example — compiler or interpreter?

      Worked example

      Question: A student is writing a program to control a robot and needs to test small parts of the code again and again while the robot is running. Should the program be compiled or interpreted? Give two reasons.

      Answer: Interpreted. First, an interpreter translates and runs one line at a time, so the student can test a small change immediately without recompiling the whole program. Second, when an error occurs the interpreter stops at that line, which makes it easier to find and fix the fault during development.

      Exam tips
      • Compiler vs interpreter questions almost always ask for a comparison — give one advantage of each, or two of the one you recommend, tied to the situation.
      • Remember the two-pass assembler: pass 1 records label addresses, pass 2 generates the code — that is why forward references work.
      • Do not say a compiler "runs the program" — it translates it; the program runs afterwards.

      6

      Security, privacy and data integrity

      Threats and defences, encryption, validation and verification.

      What you must be able to do

      • 6.1 Data security — describe threats (malware including viruses, worms and trojans; phishing; pharming; spyware; ransomware) and defensive measures (firewalls, anti-virus software, authentication, biometric controls, access rights, symmetric encryption); distinguish data privacy from data security.
      • 6.2 Data integrity — describe validation methods (range check, format check, length check, presence check, check digit) and verification methods (double data entry, visual checks, parity bits, checksums).

      6.1Threats and defences

      Malware is software written to harm: a virus attaches to files and spreads when they are shared, a worm spreads by itself across a network, and a trojan pretends to be useful software while secretly doing harm. Phishing is a fake email or message that tricks you into giving away passwords or bank details; pharming redirects you to a fake copy of a real website without you clicking anything; spyware secretly records what you type or where you browse; ransomware encrypts your files and demands payment to unlock them.

      Defences work in layers. A firewall blocks unwanted network traffic; anti-virus software scans for and removes known malware; authentication (passwords, two-factor authentication, biometrics such as fingerprints) checks that a user is who they claim to be; access rights limit what each user can see or change; and encryption scrambles data so it cannot be read without the key. In symmetric encryption the same key encrypts and decrypts the data, so the key itself must be shared safely.

      Data privacy and data security are different: privacy is about people's rights — who is allowed to collect and use personal data; security is about the safeguards that protect data from unauthorised access. A system can be secure (well protected) yet still breach privacy (collecting data it has no right to hold).

      6.2Validation and verification

      Validation checks whether data is sensible and acceptable when it is entered; verification checks whether data matches its original source. They are not the same thing, and the exam tests the difference.

      Validation methodWhat it checksExample
      Range checkThe value is between sensible limits.An exam mark must be 0–100.
      Format checkThe value matches a pattern.A date must be DD/MM/YYYY.
      Length checkThe value has the right number of characters.A password must be at least 8 characters.
      Presence checkA value has been entered at all.A name field must not be blank.
      Check digitThe last digit matches a calculation on the others.A barcode or ISBN number.

      Verification methods: double data entry (type the data twice and compare), visual checks (a person reads the entered data against the original), parity bits (an extra bit makes the number of 1s even or odd, catching single-bit errors in transmission) and checksums (a value calculated from the data, sent with it, and recalculated at the other end — if the two values differ, the data changed).

      Worked example — validation or verification?

      Worked example

      Question: A school enters students' exam marks into a system. (a) A mark of 105 is rejected. Which validation method is this, and why? (b) A teacher types each mark twice and the system compares the two entries. What is this called?

      Answer: (a) A range check: marks must be between 0 and 100, and 105 is outside that range, so the value is not sensible. (b) Double data entry — a verification method: it checks that the entered data matches what was typed the first time, not whether the mark itself is sensible.

      Exam tips
      • The most common error in this section is swapping validation and verification: validation = sensible?, verification = same as the original?
      • When a question asks for a defence against a named threat, match the defence to the threat — a firewall does not stop phishing, and anti-virus software does not stop someone guessing a password.
      • For encryption, state whether the key is the same for both sides (symmetric) — and remember the key must be shared safely.

      Section 7 — Ethics and ownership

      7

      Ethics and ownership

      Ethical issues, codes of conduct, intellectual property, copyright and open-source licensing.

      What you must be able to do

      • 7.1 Ethics and ownership — discuss ethical concerns in computing and software engineering; explain professional codes of conduct (ACM, BCS); explain intellectual property rights, software piracy and copyright law; compare open-source (FOSS) and proprietary licensing; discuss the ethical issues of artificial intelligence, including automated decision making and data profiling.

      7.1Ethics, codes of conduct and ownership

      Computers create ethical questions that did not exist before: who owns data about you, who is responsible when an automated system makes a wrong decision, and how much should a program be allowed to watch its users? Professional codes of conduct — such as those of the ACM and the BCS — set out how computing professionals should behave: act honestly, protect users' privacy, do not harm others, and take responsibility for the systems you build. A code of conduct does not have the force of law, but breaking it can cost a professional their membership and reputation.

      Intellectual property is the legal idea that creative work belongs to its creator. Copyright gives the creator the right to control copying; software piracy — copying or using software without a licence — is a breach of copyright and is illegal. A proprietary licence keeps the source code closed and charges for use; an open-source (FOSS) licence lets anyone see, change and share the code, usually for free. Open-source software is often developed by a community and can be inspected for security problems, but there may be no company to provide support or accept responsibility when it fails.

      Artificial intelligence raises its own ethical issues: an AI system that decides who gets a loan or a job can inherit the biases in its training data; data profiling builds detailed pictures of people from their behaviour, often without their full understanding; and automated decisions can be hard to explain or appeal against. When you evaluate an ethical question in the exam, name the people affected, state what is gained and what is lost, and reach a reasoned conclusion — a one-sided answer scores less than a balanced one.

      Worked example — evaluating an ethical dilemma

      Worked example

      Question: A company uses AI to shortlist job applicants from their CVs. Discuss two ethical issues this raises.

      Answer: First, bias: if the AI was trained on past hiring data that favoured one group of applicants, it will repeat that bias and reject qualified people unfairly — and the company may not even notice. Second, lack of transparency: applicants are not told how the decision was made and have no clear way to challenge it, so an unfair rejection cannot be corrected. A responsible company would audit the system for bias and keep a human in the final decision.

      Exam tips
      • Ethics questions want discussion, not just a list: give the issue, explain who is affected and how, and finish with a balanced judgement.
      • Do not confuse copyright with patents: copyright protects the expression of an idea (code, text, music); it does not protect the idea itself.
      • For open-source vs proprietary, compare the same points on both sides: cost, access to source code, support, and who is responsible when things go wrong.

      8

      Databases

      Flat files and relational databases, keys and E-R diagrams, DBMS features, SQL (DDL and DML).

      What you must be able to do

      • 8.1 Database concepts — explain the limitations of flat-file systems (data redundancy, inconsistency, data-program dependency); describe relational databases (entities, attributes, primary keys, foreign keys, compound keys, referential integrity); draw and interpret entity-relationship (E-R) diagrams (1:1, 1:M, M:N relationships).
      • 8.2 Database Management Systems (DBMS) — describe DBMS features: data dictionary, data security, access permissions, backup and recovery.
      • 8.3 DDL and DML (SQL) — write SQL using DDL (CREATE TABLE, ALTER TABLE, PRIMARY KEY, FOREIGN KEY) and DML (SELECT, FROM, WHERE, ORDER BY, GROUP BY, INNER JOIN, INSERT INTO, UPDATE, DELETE).

      8.1From flat files to relational databases

      A flat file stores all its data in one table. That causes three problems: data redundancy (the same fact is stored many times), inconsistency (updating one copy but not another leaves the data disagreeing with itself) and data-program dependency (changing the file's structure means changing every program that uses it). A relational database splits the data into linked tables, so each fact is stored once.

      Each table has a primary key — a field (or combination of fields, called a compound key) that uniquely identifies each row. A foreign key is a primary key from another table, stored in this table to create the link. Referential integrity is the rule that a foreign key must match a real primary key in the other table — you cannot record an order for a customer who does not exist.

      An E-R diagram shows the tables (entities) and how they relate: 1:1 (one row links to exactly one row, such as a person and their passport), 1:M (one row links to many, such as one customer and many orders) and M:N (many to many, such as students and courses). An M:N relationship cannot be built directly — it must be split into two 1:M relationships using a junction table in the middle.

      8.2What a DBMS provides

      A DBMS is the software that manages the database. It keeps a data dictionary (the definitions of every table, field and data type), enforces data security and access permissions (who can read or change what), and provides backup and recovery (so the database can be restored after a failure). Because programs use the DBMS instead of reading files directly, the data is independent of the programs — this is called logical data independence.

      8.3SQL: DDL and DML

      DDL (Data Definition Language) builds the structure; DML (Data Manipulation Language) works with the data inside it.

      -- DDL: create a table with a primary key and a foreign key
CREATE TABLE Orders (
  OrderID INTEGER PRIMARY KEY,
  CustomerID INTEGER,
  OrderDate DATE,
  FOREIGN KEY (CustomerID) REFERENCES Customers (CustomerID)
);

-- DML: list the names of customers who ordered after 1 June 2026
SELECT Customers.Name, Orders.OrderDate
FROM Customers
INNER JOIN Orders ON Customers.CustomerID = Orders.CustomerID
WHERE Orders.OrderDate > '2026-06-01'
ORDER BY Orders.OrderDate;

      The INNER JOIN connects the two tables on the matching key, so each order appears next to the name of the customer who placed it. Other DML you must know: INSERT INTO (add a row), UPDATE (change a row), DELETE (remove a row), GROUP BY (group rows, for example to count orders per customer) and ORDER BY (sort the results).

      Worked example — designing the tables

      Worked example

      Question: A library lends books to members. A member can borrow many books, and a book can be borrowed by many members over time. Draw the E-R design and name the keys.

      Answer: This is an M:N relationship between Member and Book, so it needs a junction table — call it Loan. Member has primary key MemberID; Book has primary key BookID; Loan has a compound primary key (MemberID, BookID) — both fields are also foreign keys, one to Member and one to Book — plus fields such as DateBorrowed and DateReturned. The junction table turns one M:N relationship into two 1:M relationships, and referential integrity stops a loan being recorded for a member or book that does not exist.

      Exam tips
      • Learn the SQL keywords exactly, including commas and the semicolon at the end — the exam gives marks for correct syntax.
      • When a question asks for a JOIN, always state which fields link the tables (primary key to foreign key).
      • For E-R questions, first decide the relationship type (1:1, 1:M or M:N) — everything else follows from it.
      • Do not use a flat file where a relational database is asked for: name the redundancy and inconsistency problems the flat file would cause.

      9

      Algorithm design and problem solving

      Computational thinking, flowcharts and pseudocode, linear and binary search, bubble sort, trace tables.

      What you must be able to do

      • 9.1 Computational thinking skills — use abstraction, decomposition, pattern recognition and algorithm design to break a problem down.
      • 9.2 Algorithms — express algorithms with structured flowcharts and standard Cambridge pseudocode; explain and use linear search, binary search and bubble sort; build dry-run trace tables to check logic and find errors.

      9.1Computational thinking

      Decomposition
      Splitting a big problem into smaller sub-problems. "Run a school library" splits into: add a book, lend a book, return a book, list overdue books.
      Abstraction
      Keeping only the details that matter and ignoring the rest. For lending a book, you need the book ID, the member ID and the date — not the colour of the book's cover.
      Pattern recognition
      Spotting that a new problem is like one you have solved before, so you can reuse the solution — for example, searching a list of students is the same problem as searching a list of books.
      Algorithm design
      Writing the steps in a clear order, with decisions and repeats where needed, so that anyone (or any computer) can follow them exactly.

      9.2Searching and sorting

      AlgorithmHow it worksWhen to use it
      Linear searchCheck each item in turn, from the first to the last, until you find the one you want.Any list, in any order. Simple, but slow for long lists.
      Binary searchLook at the middle item of a sorted list: if it is too big, search the left half; if too small, search the right half; repeat.Only on a sorted list. Very fast — it halves the search space at every step.
      Bubble sortCompare neighbouring pairs and swap them if they are in the wrong order; repeat passes until a whole pass makes no swaps.Small lists, or teaching the idea of sorting. Slow for long lists.

      A trace table is how you prove an algorithm works — and how you find its bugs. Write one column for each variable, one row for each step, and update the values exactly as the algorithm would. If the trace table disagrees with what you expected, the algorithm (or your understanding of it) is wrong.

      Worked example — binary search trace

      Worked example

      Question: Use binary search to find 42 in the sorted list [5, 12, 23, 31, 42, 57, 68, 79]. Show the low, high and mid positions at each step.

      Answer: Low = 1, High = 8. Mid = (1 + 8) div 2 = 4, value 31. 31 < 42, so search the right half: Low = 5. Mid = (5 + 8) div 2 = 6, value 57. 57 > 42, so search the left half: High = 5. Mid = (5 + 5) div 2 = 5, value 42. Found at position 5, after three comparisons. A linear search would have needed five.

      Exam tips
      • Binary search only works on a sorted list — if the question does not say the list is sorted, use linear search.
      • Trace tables earn marks even when the final answer is wrong, so write them out fully, one row per step.
      • Use Cambridge pseudocode in Paper 2 answers (FOR...NEXT, WHILE...ENDWHILE, IF...THEN...ELSE...ENDIF) — Python syntax is not accepted there.
      • When comparing algorithms, count comparisons: binary search roughly halves the list each time, linear search checks each item in turn.

      Data types and structures

      What you must be able to do

      • 10.2 Arrays — declare, index, traverse and manipulate one-dimensional and two-dimensional arrays.
      • 10.3 Files — read from and write to sequential and random text files (OPENFILE, READFILE, WRITEFILE, CLOSEFILE).
      • 10.4 Abstract data types (ADTs) — explain and implement stacks, queues and linked lists using one-dimensional arrays.

      10.1–10.2Types, records and arrays

      Choosing the right data type matters: an age is an INTEGER, a price is a REAL, a single letter is a CHAR, a name is a STRING, a yes/no answer is a BOOLEAN, and a date of birth is a DATE. A record groups different types of data about one thing under one name — for example a student record with a name (STRING), an age (INTEGER) and a grade (CHAR). In pseudocode:

      TYPE Student
  DECLARE Name : STRING
  DECLARE Age : INTEGER
  DECLARE Grade : CHAR
ENDTYPE
DECLARE ClassList : ARRAY[1:30] OF Student

      An array stores many values of the same type under one name, reached by an index. A one-dimensional array is a list (for example Scores[1:10]); a two-dimensional array is a table (for example Grid[1:5, 1:5] for a board game). Arrays are fixed in size and indexed from a known starting point — know whether your array starts at 0 or 1, because the exam tests this.

      10.3Files

      A sequential file is read from the start to the end, one record at a time; a random file lets you jump straight to any record. Text files are usually sequential. The pseudocode you must know is:

      OPENFILE "results.txt" FOR READ
READFILE "results.txt", Line
WHILE NOT EOF("results.txt")
  OUTPUT Line
  READFILE "results.txt", Line
ENDWHILE
CLOSEFILE "results.txt"

      Always close a file after using it, and always check for the end of file (EOF) when reading — reading past the end of a file is a common error.

      10.4Stacks, queues and linked lists

      A stack is last-in, first-out (LIFO): you push items on the top and pop them off the top, like a pile of plates. A queue is first-in, first-out (FIFO): items join at the back and leave from the front, like a queue of people. A linked list is a chain of nodes, where each node holds data and a pointer to the next node — items can be inserted or removed anywhere in the chain without moving the others. All three can be built from a one-dimensional array: a stack needs a top pointer, a queue needs front and rear pointers, and a linked list needs a head pointer plus a free-list pointer for empty spaces.

      Worked example — stack trace

      Worked example

      Question: A stack is empty. Push 5, push 8, pop, push 3, pop, pop. What is popped each time, and what is left on the stack?

      Answer: Push 5 → [5]. Push 8 → [5, 8]. Pop → 8 is removed, leaving [5]. Push 3 → [5, 3]. Pop → 3 is removed, leaving [5]. Pop → 5 is removed, leaving the stack empty. The values come out in reverse order of how they went in: 8, then 3, then 5. That is LIFO.

      Exam tips
      • State LIFO for a stack and FIFO for a queue — and use them: a question that asks for the order items come out is testing exactly this.
      • When implementing an ADT in an array, name the pointers you need (top for a stack, front and rear for a queue, head and free-list for a linked list).
      • For file questions, write the OPENFILE, the loop with the EOF test, and the CLOSEFILE — missing the close is a lost mark.
      • Check array bounds in your answers: reading Scores[11] in an array declared [1:10] is an error.

      11.1–11.2Building blocks

      Every program is built from three constructs. Sequence is one step after another. Selection chooses a path: IF...THEN...ELSE...ENDIF for two paths, and CASE OF...ENDCASE when one value can take several different paths (such as a menu choice). Iteration repeats steps: a FOR loop repeats a known number of times, a WHILE loop repeats while a condition is true (and may run zero times), and a REPEAT...UNTIL loop always runs at least once and stops when its condition becomes true.

      // Count how many marks are passes (50 or more) in an array of 20 marks
Passes ← 0
FOR Index ← 1 TO 20
  IF Marks[Index] >= 50 THEN
    Passes ← Passes + 1
  ENDIF
NEXT Index
OUTPUT "Passes: ", Passes

      11.3Procedures, functions and parameters

      A procedure carries out a task and returns nothing; a function returns a value. Both take parameters — values passed in when they are called. Parameters can be passed by value (a copy is passed, so changes inside the subprogram do not affect the caller's variable) or by reference (the address is passed, so changes inside the subprogram do change the caller's variable). Use by value when you only need to read the data, and by reference when the subprogram must change it — for example when a sort routine must reorder the caller's array.

      Scope is where a variable can be used. A local variable exists only inside the subprogram that declares it; a global variable can be used anywhere in the program. Good programs use local variables wherever possible, because a global variable can be changed by any part of the program, which makes errors hard to find.

      # Python: a function that returns a value, and a procedure-like function
def average(marks):
    total = 0
    for mark in marks:
        total = total + mark
    return total / len(marks)

scores = [62, 71, 55, 80]
print("Average:", average(scores))

      Worked example — by value or by reference?

      Worked example

      Question: A procedure Double(Number) doubles the value passed to it. If Number is passed by value and the caller passes 7, what is the caller's variable afterwards? What if it is passed by reference?

      Answer: By value: the procedure works on a copy, so the caller's variable is still 7 — the doubled value is lost unless the procedure returns it. By reference: the procedure works on the caller's variable itself, so afterwards it holds 14.

      Exam tips
      • Paper 2 answers must be in pseudocode, not Python — write ← for assignment and use the Cambridge keywords.
      • Know the difference between WHILE and REPEAT-UNTIL: WHILE tests first and may run zero times; REPEAT-UNTIL always runs at least once.
      • When a question asks why to use a procedure, give a reason: the code is reused, the program is easier to read, or a fault is easier to find.
      • For by value vs by reference, always say what happens to the caller's variable — that is what the question is testing.

      12

      Software development

      The software development life cycle, program design, testing and maintenance.

      What you must be able to do

      • 12.1 Program development life cycle — describe the stages of the software development life cycle and compare the Waterfall, Iterative and Agile methodologies.
      • 12.2 Program design — use structure charts, state-transition diagrams and pseudocode to design a program.
      • 12.3 Program testing and maintenance — describe stub testing, black-box and white-box testing, and normal, boundary and erroneous test data; describe maintenance types (corrective, adaptive, perfective).

      12.1Life cycles

      Building software follows stages: analysis (what is needed), design (how it will work), implementation (writing the code), testing (finding the faults) and maintenance (keeping it working after delivery). The Waterfall model does each stage once, in order — it is simple and easy to manage, but a mistake found late is expensive to fix. The Iterative model builds the system in small versions, improving it each time — feedback comes earlier, but the project can grow without a clear end. Agile works in short cycles with the customer involved throughout — it adapts well to changing requirements, but it needs an experienced team and constant communication.

      12.2Design tools

      Before writing code, design it. A structure chart shows the program broken into modules in a tree, with the main module at the top. A state-transition diagram shows the states a system can be in (for example a traffic light: red, red-amber, green, amber) and the events that move it between states. Pseudocode describes the logic of each module in words. Design first, code second — it is far cheaper to fix a design than to rewrite a program.

      12.3Testing and maintenance

      Stub testing replaces a module that is not written yet with a simple stand-in, so the rest of the program can be tested early. Black-box testing tests what the program does (inputs and outputs) without looking at the code; white-box testing tests the code itself, checking that every path through it runs correctly. Good test data covers three kinds: normal data (ordinary values that should be accepted), boundary data (values at the very edge of what is allowed, such as 0 and 100 for a mark) and erroneous data (values that should be rejected, such as −5 or "abc" for a mark).

      After delivery, a program still needs maintenance: corrective (fixing faults found by users), adaptive (changing the program because the world changed — a new law, a new operating system) and perfective (improving it, for example making it faster or adding a feature users asked for).

      Worked example — choosing test data

      Worked example

      Question: A program accepts an age from 0 to 120. Give one normal, one boundary and one erroneous test value, and say what should happen for each.

      Answer: Normal: 25 — accepted, the program continues. Boundary: 0 and 120 — both accepted, because they are the exact limits; 121 would be rejected. Erroneous: −3 (or "twenty") — rejected with an error message. Boundary values are the ones programmers forget to test, and they are where most errors hide.

      Exam tips
      • Test-data questions want three kinds — normal, boundary, erroneous — with a value and the expected result for each.
      • Black-box vs white-box is a favourite comparison: black-box tests the outside (inputs/outputs), white-box tests the inside (code paths).
      • For life-cycle questions, match the methodology to the situation: a fixed, well-understood project suits Waterfall; a project whose requirements keep changing suits Agile.

      13

      Data representation

      User-defined data types, file organisation and access, floating-point numbers.

      What you must be able to do

      • 13.1 User-defined data types — explain composite types (records, sets, classes) and non-composite types (enumerated types, pointer types).
      • 13.2 File organisation and access — compare serial, sequential and random file organisation; explain sequential and direct (random) access; explain hashing and how collisions are resolved (open addressing, chaining).
      • 13.3 Floating-point numbers, representation and manipulation — explain two's complement floating-point representation (mantissa and exponent); normalise floating-point numbers; explain the trade-off between precision and range, and underflow, overflow and rounding/truncation errors.

      13.1User-defined data types

      Built-in types (INTEGER, REAL, CHAR, STRING, BOOLEAN) are not always enough, so programmers define their own. Composite types combine other types: a record groups different types under one name, a set is a collection of values of the same type with no duplicates, and a class groups data with the methods that work on it. Non-composite types are single values with a restricted set of possibilities: an enumerated type lists every allowed value (for example TYPE Day = (Mon, Tue, Wed, Thu, Fri)), and a pointer type holds the address of another value — pointers are what make dynamic data structures such as linked lists possible.

      13.2File organisation, access and hashing

      Files can be organised in three ways. In a serial file, records are stored in the order they arrive, with no sorting. In a sequential file, records are stored in key order, so they must be read from the start to find one. In a random file, each record sits at a position calculated from its key, so any record can be reached directly. Sequential access reads records one after another; direct (random) access jumps straight to the record wanted.

      Hashing turns a key into a record address with a hash function — for example, take the key modulo the number of records. A collision happens when two different keys hash to the same address. It is resolved by open addressing (look for the next free space) or chaining (keep a list of all records that share that address).

      13.3Floating-point numbers

      Very large and very small numbers are stored in floating-point form: a mantissa (the significant digits) and an exponent (how far to move the point). In two's complement floating-point, the mantissa is a two's complement fraction and the exponent is a two's complement integer. A number is normalised when its mantissa starts with 01 (positive) or 10 (negative) — normalisation uses the available bits as well as possible, giving maximum precision.

      There is always a trade-off: more bits for the mantissa gives more precision (more significant digits), more bits for the exponent gives more range (bigger and smaller numbers) — you cannot have both with a fixed number of bits. Overflow is when a result is too large to store; underflow is when a result is too small (too close to zero) to store. Rounding error comes from keeping only some digits; truncation error comes from simply cutting off the rest.

      Worked example — normalising a floating-point number

      Worked example

      Question: A floating-point number uses an 8-bit mantissa and a 4-bit exponent. The value 0.001011 × 23 is not normalised. Normalise it and explain why.

      Answer: The mantissa 0.001011 starts with 00, so it is not normalised. Shift the mantissa left until it starts with 01, adjusting the exponent each time: 0.001011 × 23 = 0.01011 × 22 = 0.1011 × 21. The normalised form is mantissa 0.1011 with exponent 1. It uses the same value, but the leading zeros are gone, so the mantissa holds more significant digits — that is the extra precision normalisation gives.

      Exam tips
      • Normalisation: positive mantissa must start with 01, negative with 10 — check the first two bits before you do anything else.
      • For hashing questions, always name the collision and the resolution method (open addressing or chaining).
      • When asked about precision vs range, say which one improves when bits move from the exponent to the mantissa — and that the total stays the same.
      • Enumerated types are a favourite one-mark question: they are an ordered, finite list of allowed values.

      14

      Communication and internet technologies

      Protocols and the OSI/TCP-IP models, circuit vs packet switching, peer-to-peer file sharing.

      What you must be able to do

      • 14.1 Protocols — explain the OSI 7-layer model and the TCP/IP 4-layer model; explain the function of IP, TCP, UDP, HTTP, HTTPS, FTP, POP3, IMAP and SMTP.
      • 14.2 BitTorrent protocol — explain how BitTorrent provides peer-to-peer file sharing; compare circuit switching and packet switching.

      14.1Layered models and protocols

      Networks are described in layers, so that each layer only has to talk to the layers next to it. The OSI model has seven layers (physical, data link, network, transport, session, presentation, application); the TCP/IP model has four (network access, internet, transport, application). The exam expects you to know what each layer does in general terms, not to memorise every detail.

      ProtocolWhat it does
      IPAddresses packets and routes them between networks.
      TCPReliable delivery: splits data into packets, numbers them, checks they arrive and resends any that are lost, and puts them back in order.
      UDPFast, connectionless delivery with no checking: packets may arrive out of order or not at all. Used where speed matters more than perfection, such as live video and online games.
      HTTP / HTTPSTransfer web pages; HTTPS adds encryption (TLS) so the data cannot be read in transit.
      FTPTransfer files between computers.
      SMTPSend email from a client to a mail server, and between mail servers.
      POP3 / IMAPReceive email: POP3 downloads mail and usually deletes it from the server; IMAP keeps mail on the server so it can be read from many devices.

      TCP is connection-oriented and reliable; UDP is connectionless, fast and unacknowledged. That one sentence answers many comparison questions: choose TCP when every byte must arrive correctly (a file download, a web page), and UDP when a small loss does not matter but delay does (a phone call, a live stream).

      14.2Switching and BitTorrent

      Circuit switching reserves a dedicated path for the whole conversation before any data is sent — like an old telephone call. It gives a guaranteed quality but wastes the path when nobody is speaking. Packet switching splits data into packets that travel independently and share the network with other traffic — it uses bandwidth efficiently, but packets can be delayed or arrive out of order.

      BitTorrent is peer-to-peer file sharing: a file is split into small pieces, and each computer (peer) downloads pieces from many other peers and uploads the pieces it already has to others. There is no central server holding the file, so the more people downloading, the faster it goes — the opposite of a normal download, where more users slow the server down. A tracker keeps a list of which peers have which pieces.

      Worked example — TCP or UDP?

      Worked example

      Question: A student is watching a live football match online. The picture occasionally freezes for a second but then continues. Which protocol is being used, and why is it the right choice?

      Answer: UDP. A live stream cannot wait for lost packets to be resent — by the time a retransmission arrived, the moment would have passed. UDP sends the packets as fast as possible and accepts that a few may be lost, which is exactly the brief freeze the student sees. TCP would be wrong here: resending lost packets would delay the stream and make it fall behind the live match.

      Exam tips
      • Learn the protocol table as pairs: TCP/UDP (reliable vs fast), POP3/IMAP (download-and-delete vs keep-on-server), HTTP/HTTPS (plain vs encrypted).
      • For switching questions, the key contrast is dedicated path vs shared bandwidth — and which one wastes capacity when idle.
      • BitTorrent questions usually ask why it gets faster with more users: every new peer is also a new source of pieces.

      15.1Processors, parallelism and virtual machines

      RISC (reduced instruction set) processors have a small set of simple instructions, each taking about one clock cycle, with many registers — they are fast and energy-efficient. CISC (complex instruction set) processors have a large set of instructions, including complex ones that do several things at once, with fewer registers — each instruction is more powerful but takes more cycles. Modern processors often mix both ideas.

      Pipelining overlaps the stages of the fetch-decode-execute cycle: while one instruction is being executed, the next is being decoded and the one after that is being fetched — like an assembly line. A pipeline hazard happens when this overlap breaks down, for example when an instruction needs a result that has not been calculated yet, or when a jump changes the flow of instructions; the pipeline must stall (a "bubble") until the problem clears.

      Parallel processing uses several processors at once. Flynn's taxonomy describes the four combinations of instruction streams and data streams: SISD (one instruction, one set of data — an ordinary single processor), SIMD (one instruction applied to many sets of data at once — graphics processing), MISD (many instructions on one set of data — rare, used in fault-tolerant systems) and MIMD (many instructions on many sets of data — a cluster of computers, or a multi-core processor). A massively parallel computer links thousands of processors together for very large problems such as weather forecasting.

      A virtual machine is a computer simulated in software: a hypervisor runs on the host hardware and lets several guest operating systems run on one physical machine, each believing it has its own computer. Benefits: better use of hardware, easy backup (copy the whole virtual machine), and safe testing. Limitations: each virtual machine shares the physical hardware, so performance is lower than running directly on the machine, and the hypervisor itself needs managing.

      15.2Boolean algebra, adders, flip-flops and K-maps

      De Morgan's laws let you swap between AND and OR with NOT: NOT (A AND B) = (NOT A) OR (NOT B), and NOT (A OR B) = (NOT A) AND (NOT B). They are the main tool for simplifying expressions — and for turning a circuit that needs one kind of gate into a circuit that uses only NAND or only NOR gates.

      A half adder adds two single bits: the sum is A XOR B and the carry is A AND B. A full adder adds two bits plus a carry-in, so it can be chained to add whole numbers. A flip-flop is a circuit that remembers one bit: an SR flip-flop sets (S = 1) or resets (R = 1) its output, and a JK flip-flop adds a toggle mode (J = K = 1 flips the output). Flip-flops are the building blocks of registers and memory.

      A Karnaugh map (K-map) is a grid for simplifying Boolean expressions visually: the cells are arranged so that neighbouring cells differ in only one variable (Gray code order), and you group adjacent 1s in blocks of 1, 2, 4 or 8. Each group removes one variable from the expression. A 2-variable K-map has 4 cells, a 3-variable map has 8, and a 4-variable map has 16.

      Worked example — De Morgan's laws in action

      Worked example

      Question: Simplify X = NOT (A AND B) and write the result using only OR and NOT.

      Answer: By De Morgan's first law, NOT (A AND B) = (NOT A) OR (NOT B). So the circuit needs two NOT gates and one OR gate, and no AND gate at all. Check with a truth table: when A = 1 and B = 1, A AND B = 1 so X = 0; (NOT A) OR (NOT B) = 0 OR 0 = 0. When A = 0 and B = 1, A AND B = 0 so X = 1; (NOT A) OR (NOT B) = 1 OR 0 = 1. The two expressions agree on every row.

      Exam tips
      • Learn De Morgan's laws by heart — they appear in almost every Paper 3.
      • For K-maps, group the largest possible blocks of 1s (1, 2, 4 or 8 cells) and remember that the edges of the map wrap around.
      • Half adder: sum = XOR, carry = AND. Full adder: add the carry-in as well — draw it as two half adders plus an OR gate.
      • Pipeline hazard questions want the cause (a result not ready yet, or a jump) and the effect (the pipeline stalls).

      16.1Scheduling and memory management

      When several programs want the processor, the operating system's scheduler decides the order. First Come First Served (FCFS) runs jobs in arrival order — simple, but a long job can block everything behind it. Shortest Job First (SJF) runs the quickest job first, which keeps waiting times low, but a long job can be starved. Shortest Remaining Time (SRT) is the preemptive version of SJF: if a shorter job arrives, the current job is paused. Round Robin gives each job a fixed time slice in turn — fair, and good for interactive systems, but switching jobs costs time. Multi-level feedback queues move jobs between queues based on how they behave, giving interactive jobs priority over long background jobs.

      Paging divides memory into fixed-size blocks (pages) so a program's pages can be scattered through physical memory; segmentation divides it into variable-size logical units (such as code and data). Virtual memory lets a program use more memory than the computer physically has, by keeping some pages on disk and loading them when needed — a page fault happens when a program needs a page that is on disk, so the operating system must fetch it. Thrashing is when the system spends most of its time swapping pages in and out of disk and almost no time doing useful work — the computer appears to freeze.

      16.2How a compiler works

      Compilation happens in phases. Lexical analysis breaks the source code into tokens (keywords, identifiers, numbers, symbols), throws away comments and whitespace, and builds the symbol table. Syntax analysis (parsing) checks the tokens against the grammar of the language and builds a parse tree — a syntax error is found here. Semantic analysis checks that the program makes sense (for example that a variable has been declared and has the right type). Code generation produces machine code, and optimisation makes it faster or smaller.

      A grammar can be written in Backus-Naur Form (BNF), using rules such as <number> ::= <digit> | <digit><number>, or drawn as a syntax diagram with the same information as a picture. A linker joins the compiled code with the libraries it needs; a loader places the finished program into memory so it can run. Libraries can be statically linked (copied into the program when it is built — bigger program, but it runs on its own) or dynamically linked (loaded from a shared file such as a DLL when the program runs — smaller program, but it needs the library file to be present).

      Worked example — Round Robin schedule

      Worked example

      Question: Three jobs arrive together. Job A needs 6 ms, Job B needs 3 ms, Job C needs 4 ms. Round Robin uses a time slice of 2 ms. In what order do the jobs finish?

      Answer: Slice 1: A runs 2 ms (4 left), B runs 2 ms (1 left), C runs 2 ms (2 left). Slice 2: A runs 2 ms (2 left), B runs 1 ms and finishes (3 ms of work done). C runs 2 ms and finishes. Slice 3: A runs its last 2 ms and finishes. Finish order: B, then C, then A. Round Robin is fair, but B — the shortest job — still had to wait for two slices before it could finish.

      Exam tips
      • Scheduling questions usually ask you to draw the timeline — label each block with the job and the time, and show the finish order.
      • Thrashing: name the cause (too many page faults, too little free memory) and the cure (add RAM, or reduce the number of programs running).
      • For compilation phases, learn the order and one thing each phase does: lexical = tokens, syntax = grammar and parse tree, semantic = meaning and types, code generation = machine code.
      • BNF: ::= means "is defined as", | means "or", and angle brackets mark a non-terminal such as <digit>.

      Security

      Asymmetric encryption, digital signatures, digital certificates and certificate authorities, SSL and TLS.

      What you must be able to do

      • 17.1 Encryption, encryption protocols and digital certificates — explain asymmetric encryption (public and private keys, the basics of RSA); explain digital signatures for authenticity, non-repudiation and message integrity; explain digital certificates and certificate authorities (CAs); describe the SSL/TLS handshake.

      17.1Public and private keys

      In symmetric encryption (Section 6) the same key encrypts and decrypts, so the key must be shared safely — and that is the hard part. Asymmetric encryption solves it with a key pair: a public key that anyone may know, and a private key that only its owner knows. Data encrypted with the public key can only be decrypted with the matching private key, so anyone can send you a secret message — but only you can read it. In RSA, the public key is built from the product of two large prime numbers, and the security comes from how hard it is to factor that product back into the two primes.

      A digital signature proves who sent a message and that it was not changed. The sender first makes a message digest (a short fingerprint of the message, made with a hash function), then encrypts the digest with their private key — that is the signature. Anyone can decrypt it with the sender's public key and compare it with a fresh digest of the message: if they match, the message is genuine and unchanged. Because only the sender holds the private key, they cannot later deny sending it — this is called non-repudiation.

      17.1Certificates and the TLS handshake

      But how do you know a public key really belongs to the person it claims to? A digital certificate answers that: it is a document containing a person's public key and identity, signed by a trusted certificate authority (CA). Your browser trusts the CA, so it trusts the certificate, so it trusts the public key. If a certificate is stolen or misused, the CA puts it on a revocation list.

      When you open a secure website, your browser and the server perform the TLS handshake: the server sends its certificate, the browser checks it, they agree on a session key (using asymmetric encryption to share it safely), and from then on they use fast symmetric encryption for the rest of the session. That is why HTTPS is secure: the handshake uses asymmetric encryption to exchange the key, and symmetric encryption to protect the data.

      Worked example — signing and checking a message

      Worked example

      Question: A teacher sends a signed exam paper to a school. Explain how the school checks the paper is genuine and unchanged, naming the keys used.

      Answer: The teacher hashes the paper to make a message digest and encrypts the digest with the teacher's private key — this is the digital signature, sent with the paper. The school decrypts the signature with the teacher's public key (from the teacher's certificate) to recover the original digest, then hashes the paper it received. If the two digests match, the paper came from the teacher and was not altered on the way. If they differ, the paper was changed — or the signature is fake.

      Exam tips
      • The most common mistake in this section is swapping the keys: encrypting with the public key keeps a message secret; signing with the private key proves who sent it.
      • For the TLS handshake, list the steps in order: certificate, check, agree a session key, switch to symmetric encryption.
      • Non-repudiation means the sender cannot deny sending the message — link it to the private key only the sender holds.

      18.1Search: A* and Dijkstra

      Many AI problems are searches through a graph of possible states — a map of roads, a maze, or the moves in a game. Dijkstra's algorithm finds the shortest path from a start node to every other node by always expanding the node with the smallest known distance so far; it is guaranteed to find the shortest path, but it explores in all directions. A* search is faster because it uses a heuristic — an estimate of the distance still to go. At each step it chooses the node with the smallest f(n) = g(n) + h(n), where g(n) is the cost so far and h(n) is the estimated cost to the goal. A* is still guaranteed to find the shortest path, provided the heuristic never overestimates the true distance.

      18.1Artificial neural networks

      An artificial neural network (ANN) is layers of simple units, loosely modelled on the brain. Each unit takes several inputs, multiplies each by a weight, adds them together with a bias, and passes the result through an activation function that decides whether the unit "fires". The network learns by backpropagation: it compares its output with the right answer, works out how much each weight contributed to the error, and adjusts the weights a little — then repeats this thousands of times over many examples. Training needs a lot of labelled data and a lot of computing power, and the trained network can be hard to explain: it works, but nobody can easily say why it gave a particular answer.

      Worked example — A* on a small graph

      Worked example

      Question: From node S, two neighbours are available: node A with g = 4 and h = 6, and node B with g = 7 and h = 2. Which node does A* expand next, and why?

      Answer: Work out f(n) = g(n) + h(n) for each: A has f = 4 + 6 = 10, B has f = 7 + 2 = 9. A* always expands the node with the smallest f, so it expands B next — even though B cost more to reach, its estimated total cost to the goal is lower. That is the point of the heuristic: it guides the search towards the goal instead of wandering in every direction like Dijkstra's algorithm.

      Exam tips
      • Learn f(n) = g(n) + h(n) and what each letter means — g is the cost so far, h is the estimated cost remaining.
      • For machine learning, the question is usually "which type, and why?" — match the data (labelled, unlabelled, or rewards) to the type.
      • For neural networks, know the order: weighted sum plus bias, then the activation function; and that backpropagation adjusts the weights to reduce the error.
      • A* is only guaranteed optimal if the heuristic never overestimates — state that condition if the question asks about guarantees.

      19.1Dynamic data structures and trees

      In Section 10 the ADTs were built from fixed arrays. At A Level they are dynamic: memory is allocated as it is needed, using pointers. A linked list is a chain of nodes, each holding data and a pointer to the next node; a binary tree is a node with at most two children (left and right); a hash table stores values at addresses computed from their keys; a dictionary stores key-value pairs so a value can be found quickly by its key. Pointers manage the links in heap memory, so the structure can grow and shrink — unlike a fixed array, which wastes space when half empty and overflows when full.

      Tree traversals visit every node of a binary tree in a fixed order. In-order traversal visits left subtree, then the node, then the right subtree — for a binary search tree this gives the values in sorted order. Pre-order visits the node first, then left, then right (useful for copying a tree). Post-order visits left, then right, then the node (useful for deleting a tree, since children are removed before their parent).

      Insertion sort builds the sorted list one item at a time: take the next unsorted item and insert it into its correct place in the sorted part. It is simple and fast on small or nearly-sorted lists, but slow on long random lists. A binary tree search starts at the root and goes left if the value is smaller, right if it is larger, until it finds the value or reaches an empty branch; inserting a value follows the same path and adds a new leaf where the empty branch was.

      19.2Recursion

      A recursive routine calls itself to solve a smaller version of the same problem. Every recursive routine needs two parts: a base case that stops the recursion (the simplest version of the problem, with a direct answer) and a recursive step that calls the routine again on a smaller problem. Each call is stored on the call stack until the base case is reached, then the calls return one by one. If the base case is missing or never reached, the calls pile up until the stack overflows and the program crashes.

      # Recursive factorial: base case n == 0, recursive step n * factorial(n - 1)
def factorial(n):
    if n == 0:          # base case
        return 1
    return n * factorial(n - 1)   # recursive step

print(factorial(4))   # 4 * 3 * 2 * 1 * 1 = 24

      Worked example — tracing recursion

      Worked example

      Question: Trace factorial(3) and show the call stack.

      Answer: factorial(3) calls factorial(2), which calls factorial(1), which calls factorial(0). The stack now holds four calls. factorial(0) hits the base case and returns 1. factorial(1) returns 1 × 1 = 1. factorial(2) returns 2 × 1 = 2. factorial(3) returns 3 × 2 = 6. The stack unwinds in reverse order — the last call made is the first to return.

      Exam tips
      • For traversal questions, write the order out in full: in-order = left, node, right; pre-order = node, left, right; post-order = left, right, node.
      • When tracing recursion, draw the call stack — one box per call, with its parameter — and unwind it from the base case upwards.
      • Every recursive answer needs the base case stated: without it, the routine never stops.
      • Insertion sort questions usually ask you to show the list after each pass — write one line per pass.

      20.1Object-oriented programming

      In object-oriented programming (OOP), a class is a blueprint and an object is one instance built from it — a class Student describes what every student has, and each actual student is an object of that class. The data an object holds are its attributes (or properties); the things it can do are its methods. Encapsulation means keeping an object's data hidden inside it and only allowing access through its methods — getters read an attribute and setters change it, so the object can check the new value first.

      Inheritance lets a new class take the attributes and methods of an existing class and add its own: a class Teacher can inherit from Person and add a staff number. Polymorphism means the same method name can behave differently in different classes — describe() might print a student's grade for a Student and a teacher's subject for a Teacher — and a program can call it without knowing which kind of object it has. Containment (aggregation) is when one object holds another as part of itself, such as a School holding a list of Students. A constructor runs when an object is created, setting up its starting values.

      # A class with a constructor, a method, inheritance and overriding
class Person:
    def __init__(self, name):
        self.name = name          # attribute
    def describe(self):
        return "Person: " + self.name

class Student(Person):            # Student inherits from Person
    def __init__(self, name, grade):
        super().__init__(name)
        self.grade = grade
    def describe(self):           # overriding: same name, new behaviour
        return "Student: " + self.name + ", grade " + self.grade

a = Student("Aung", "A")
print(a.describe())   # Student: Aung, grade A

      20.2Low-level and declarative programming

      Low-level programming is assembly language: the same five addressing modes from Section 4 (immediate, direct, indirect, indexed, relative) and the same idea that every instruction is an op-code plus an operand. Imperative (procedural) programming is the style of Sections 11 and 19: the programmer writes the steps, in order, using variables, constructs, procedures and functions.

      Declarative programming is different: instead of writing steps, you write facts and rules, and the system works out how to answer a question from them. For example, facts: parent(thiri, aung) and parent(aung, may); rule: grandparent(X, Z) IF parent(X, Y) AND parent(Y, Z). Ask "who is May's grandparent?" and the system uses the rule to answer "Thiri" — you never wrote the steps to search. Note that Paper 4 does not assess low-level or declarative programming; they are examined in Paper 3.

      Worked example — designing classes

      Worked example

      Question: A school system needs to store students and teachers. Both have a name and an email; students have a grade, teachers have a subject. Design the classes and explain how inheritance helps.

      Answer: Create a base class Person with attributes name and email and a method describe().
