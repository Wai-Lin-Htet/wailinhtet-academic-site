      Problem Solving

      What an algorithm is, how to break a problem down, and the four standard algorithms you must know: linear search, binary search, bubble sort and merge sort.

      1.1Algorithms, decomposition and abstraction

      An algorithm is a set of precise, ordered steps that solves a problem or completes a task. A good algorithm is clear enough for someone (or a computer) to follow exactly, it always finishes, and it gives the correct answer for every allowed input.

      Before you write any code, break the problem down:

      Decomposition
      Splitting a big problem into smaller sub-problems, each of which is easier to solve. For example, "build a quiz program" splits into: read the questions, ask each question, check the answer, keep the score, show the result.
      Abstraction
      Ignoring details that do not matter for the problem, and keeping only what is needed. A bus timetable app needs the route and the time; it does not need the colour of the bus.
      Algorithmic thinking
      Turning the sub-problems into a clear sequence of steps, in the right order, with decisions (selection) and repeats (iteration) where needed.

      Algorithms are written as pseudocode or drawn as flowcharts before they are coded. Pseudocode uses plain English words with a fixed structure, so it is easy to read and easy to turn into any programming language.

      First pseudocode

      These are the words you will use again and again: DECLARE to name a variable, ← to give it a value, INPUT to read a value, OUTPUT to show one, and IF … THEN … ENDIF to make a decision.

      DECLARE Height : INTEGER
INPUT Height
IF Height >= 170 THEN
    OUTPUT "Tall"
ENDIF
      Exam tip In pseudocode, ← means "gets the value of" — it is not an equals sign. Total ← Total + 5 means "take the current value of Total, add 5, and store the result back in Total". Writing = instead of ← loses marks.

      1.2Searching

      Linear search

      A linear search checks each item in turn, from the first to the last, until it finds the target or reaches the end. It works on any list — sorted or not.

      FOR Index ← 1 TO 5
    IF Names[Index] = "Aung" THEN
        OUTPUT "Found at position ", Index
    ENDIF
NEXT Index

      With n items, a linear search makes at most n comparisons. If the item is first, it takes 1 comparison (best case); if it is last or missing, it takes n comparisons (worst case). On average it takes about n ÷ 2 comparisons.

      Binary search

      A binary search only works on a sorted list. It compares the target with the middle item: if the target is smaller, it searches the left half; if larger, the right half. Each step throws away half of the list, so it is much faster than a linear search on a long list.

      Linear searchBinary search
      List must be sorted?NoYes
      Comparisons (worst case, n items)nlog2 n, rounded up
      Best forShort lists, or lists that change oftenLong lists that stay sorted, such as a dictionary

      Worked example: binary search

      Sorted list: 3, 7, 12, 19, 24, 31, 38. Find 31.

      1. Middle of 7 items is position 4: 19. 31 > 19, so search the right half: 24, 31, 38.
      2. Middle of the right half is 31. Found — in only 2 comparisons. A linear search would have needed 6.

      With 1,000 sorted items, a binary search needs at most 10 comparisons (210 = 1,024), while a linear search could need 1,000.

      Common mistakes
      • Using a binary search on an unsorted list — it will give the wrong answer.
      • Forgetting that the list must be sorted first; sorting takes time too.
      • Mixing up best and worst case: the best case for a linear search is 1 comparison, not 0.

      1.3Sorting

      Bubble sort

      A bubble sort compares neighbouring pairs and swaps them if they are in the wrong order. After each pass, the largest unsorted item has "bubbled" to the end. Passes repeat until a pass makes no swaps.

      Try it: bubble sort stepper

      Type your own numbers, separated by commas, then press Step to watch each comparison.

      Worked example: bubble sort

      Sort 5, 1, 4, 2, 8 into ascending order.

      1. Pass 1: 5 > 1 swap → 1, 5, 4, 2, 8; 5 > 4 swap → 1, 4, 5, 2, 8; 5 > 2 swap → 1, 4, 2, 5, 8; 5 < 8 no swap. The 8 is now in its final place.
      2. Pass 2: 1 < 4, 4 > 2 swap → 1, 2, 4, 5, 8; 4 < 5. The 5 is in place.
      3. Pass 3: 1 < 2, 2 < 4 — no swaps. The list is sorted: 1, 2, 4, 5, 8.

      Merge sort

      A merge sort splits the list in half again and again until every piece has one item, then merges the pieces back together in order.

      Sort 38, 27, 43, 3, 9, 82, 10:

      1. Split: [38, 27, 43, 3] and [9, 82, 10]; keep splitting to single items.
      2. Merge in order: [27, 38] and [3, 43] merge to [3, 27, 38, 43]; [9, 10, 82] on the other side.
      3. Final merge: [3, 9, 10, 27, 38, 43, 82].
      Bubble sortMerge sort
      How it worksSwaps neighbouring pairs, pass by passSplits the list, then merges it back in order
      Speed on a long listSlow — many comparisons and swapsFast — far fewer comparisons on large lists
      Extra memoryNone — sorts in placeNeeds extra space for the merged lists
      Best forShort lists, or lists that are nearly sortedLong lists, where speed matters
      Exam tip When a question asks you to "show the steps" of a sort, write out the list after every swap (bubble sort) or after every merge (merge sort). Examiners give marks for the working, even if the final list has a small slip. Always state how many comparisons a search makes — that is often the mark.

      Programming

      Writing and debugging programs in Python: sequence, selection and iteration, data types, arrays, operators and subprograms.

      2.1Sequence, selection and iteration

      Every program is built from three constructs:

      Sequence
      Instructions run one after another, in order. The program starts at the top and works down.
      Selection
      The program chooses a path with a condition — if, elif and else in Python.
      Iteration
      The program repeats a block — a for loop when you know how many times, a while loop when you do not.
      mark = int(input("Mark (0-100): "))
if mark >= 50:
    print("Pass")
elif mark >= 40:
    print("Borderline")
else:
    print("Fail")

      Indentation matters in Python. The lines inside an if or a loop must be indented by the same amount (usually 4 spaces). A line with the wrong indentation is a syntax error, and a line that is not indented at all runs outside the if or loop — a logic error that is easy to miss.

      • = assigns a value; == compares two values. if age = 18: is a syntax error.
      • Forgetting to cast input() before arithmetic.
      • Comparing a string with a number, e.g. if mark > "50": — a runtime error.

      2.4Selection and iteration in Python

      for i in range(1, 6):        # count-controlled: runs 5 times
    print(i)

count = 1
while count <= 5:           # condition-controlled: runs while true
    print(count)
    count = count + 1

      Use a for loop when you know how many times to repeat (a fixed number, or once per item in a list). Use a while loop when the repeat depends on a condition, such as "keep asking until the answer is correct". A while loop with a condition that never becomes false runs forever — always make sure the condition can change inside the loop.

      Nested loops and selection

      for row in range(1, 4):
    for col in range(1, 4):
        print(row * col, end=" ")
    print()

      The inner loop runs completely for every single run of the outer loop. Trace tables (Practical 3) are the best way to follow nested loops without getting lost.

      2.5One- and two-dimensional arrays

      An array stores several values of the same type under one name, each with an index. In Python, arrays are lists. The first item is at index 0.

      scores = [72, 58, 91, 64]     # one-dimensional array (a list)
print(scores[0])              # 72 — the first item
print(scores[2])              # 91 — the third item
scores[1] = 60                # change the second item
print(len(scores))            # 4 — the number of items

# two-dimensional array: a list of lists (rows and columns)
grid = [[1, 2, 3],
        [4, 5, 6]]
print(grid[1][2])             # 6 — row 1, column 2

      To work through an array, loop over its indexes or its items. To find the largest value, start with the first item as the largest so far, then compare each other item in turn.

      2.6Subprograms with parameters

      A subprogram is a named block of code that does one job. A function returns a value; a procedure does something but returns nothing. Parameters let the same subprogram work on different values.

      def area(length, width):     # length and width are parameters
    return length * width

room = area(5, 4)             # call with arguments 5 and 4
print(room)                   # 20

      Variables made inside a subprogram are local — they exist only while the subprogram runs. Variables made outside are global. A subprogram should use its parameters and its return value, not reach out to global variables: that keeps it reusable and easier to test.

      Exam tip When a question asks you to "write a program", plan it in three lines first: what is the input, what is the processing, what is the output. Then write the code in that order. Check your program by hand with one simple test value before you call it finished — examiners award marks for correct logic even if one line has a small slip.

      Data

      Binary and hexadecimal, how text, images and sound are stored, storage units, compression and encryption.

      3.1Binary and hexadecimal

      A computer stores everything as binary — patterns of 0 and 1 — because its circuits have two states: off and on. Hexadecimal (base 16) is a shorthand for people: one hex digit stands for exactly four bits.

      SystemBaseDigits used
      Denary (decimal)100–9
      Binary20, 1
      Hexadecimal160–9, A–F (A = 10, F = 15)

      To convert binary to denary, add the place values where the bit is 1: 10011100 = 128 + 16 + 8 + 4 = 156. To convert to hex, split into groups of four bits: 1001 1100 → 9 and C → 9C.

      Try it: converter

      Type in any box (0 to 255). The other two update.

      Binary addition and overflow

      Work column by column from the right: 0 + 0 = 0; 0 + 1 = 1; 1 + 1 = 0 carry 1; 1 + 1 + 1 = 1 carry 1. Overflow happens when the answer needs more bits than the register holds — in 8 bits the largest value is 255, so 182 + 107 = 289 overflows and the stored answer is wrong.

      Negative numbers: two's complement

      In two's complement the left-most bit has the value −128 instead of +128, so the 8-bit range is −128 to +127. To find −45: write 45 as 00101101, invert every bit (11010010), then add 1 (11010011).

      Logical shifts

      A left shift by 1 multiplies by 2; a right shift by 1 divides by 2 (whole number). Bits that fall off the end are lost, so shifting can lose precision or cause overflow.

      3.2How text, images and sound are stored

      Text

      Every character is given a number in a character set and stored in binary. ASCII uses 7 bits (128 characters: English letters, digits, punctuation). Unicode uses up to 32 bits and covers almost every language, including Myanmar script and emoji — but the same text takes more storage than ASCII.

      Images

      An image is a grid of pixels. Each pixel stores a colour as a binary number; the colour depth is the number of bits per pixel (24-bit colour = 8 bits each for red, green and blue). The resolution is the number of pixels (width × height). File size = width × height × colour depth (in bits) ÷ 8.

      Worked example: a 1920 × 1080 photo at 24-bit colour = 1920 × 1080 × 24 bits = 49,766,400 bits = 6,220,800 bytes (about 6 MB) before compression.

      Sound

      Sound is stored as a series of samples. The sample rate is how many samples are taken per second (44,100 per second for CD quality). The bit depth is how many bits each sample uses (16 bits for CD). File size = sample rate × bit depth × duration (in seconds) × number of channels ÷ 8.

      Worked example: 10 seconds of CD-quality stereo sound = 44,100 × 16 × 10 × 2 ÷ 8 = 1,764,000 bytes (about 1.7 MB).

      Exam tip For file-size questions, write the formula first, then substitute the numbers, then give the answer with its unit. Marks are given for the method even if the final arithmetic slips. Remember: divide bits by 8 to get bytes.

      3.4Compression

      Compression makes files smaller so they use less storage and transfer faster.

      LosslessLossy
      Original dataCan be rebuilt exactlySome data permanently removed
      Size reductionSmallerMuch smaller
      ExamplesPNG, FLAC, ZIP, run-length encoding (RLE)JPEG, MP3, MP4
      Best forText, program files, medical imagesPhotos, music and video on the web

      Run-length encoding (RLE): store each value once with a count of how many times it repeats. AAAABBBCC becomes 4A3B2C. It works best on data with long runs, such as simple graphics. Lossy compression works by reducing resolution, colour depth or sample rate and dropping detail people barely notice.

      3.5Encryption

      Encryption scrambles readable plaintext into unreadable ciphertext using an algorithm and a key. It does not stop data being intercepted — it makes intercepted data useless without the key.

      Caesar cipher

      Each letter is shifted a fixed number of places along the alphabet. With a shift of 3, A → D, B → E, and Z wraps round to C. "HELLO" becomes "KHOOR". It is easy to break: there are only 25 possible shifts, so an attacker can try them all.

      Vigenère cipher

      Each letter is shifted by a different amount, taken from a keyword that repeats. With the keyword "KEY", the shifts are 10, 4, 24, 10, 4, 24 … (K = 10, E = 4, Y = 24). The same letter encrypts to different letters in different positions, which makes it much harder to break than a Caesar cipher — but it is still breakable if the keyword is short or the message is long.

      Symmetric encryptionAsymmetric encryption
      KeysOne secret key encrypts and decryptsA key pair: public key encrypts, private key decrypts
      Main problemThe key must be shared, and could be stolen on the waySlower, but the private key is never sent to anyone
      Used forEncrypting large amounts of dataExchanging keys safely, for example in HTTPS
      Common mistakes
      • Saying encryption "stops hacking" — it does not stop data being stolen, it makes stolen data unreadable.
      • Confusing compression with encryption: compression makes files smaller, encryption makes them secret.
      • Forgetting the unit when you give a file size (bytes, KB or MB).

      Computers

      How a computer works: the input–process–output model, the CPU and the fetch–decode–execute cycle, logic gates, operating systems and programming languages.

      4.1The input–process–output model

      Every computer system follows the same pattern: input → process → output, with storage holding data and programs.

      Input devices
      Keyboard, mouse, scanner, microphone, camera, sensors — they put data into the system.
      Processor (CPU)
      Carries out instructions and calculations on the data.
      Output devices
      Monitor, printer, speakers, actuators — they present results or cause an action.
      Storage
      Main memory (RAM and ROM) for data in use now; secondary storage (hard drive, SSD, USB stick) for data kept long term.
      RAMROM
      Volatile?Yes — loses data when power is offNo — keeps data without power
      Can it be changed?Yes — read and writeMostly read-only (holds the boot program)
      SpeedFastSlower than RAM

      4.2The CPU and the fetch–decode–execute cycle

      The central processing unit (CPU) follows the Von Neumann architecture: program instructions and data are stored together in main memory and fetched one at a time.

      Arithmetic logic unit (ALU)
      Carries out calculations and logical comparisons.
      Control unit (CU)
      Fetches and decodes instructions and sends control signals to coordinate the rest of the computer.
      Program counter (PC)
      Holds the address of the next instruction.
      Memory address register (MAR)
      Holds the address of the memory location to be read from or written to.
      Memory data register (MDR)
      Holds the data or instruction just fetched from memory, or about to be written to it.
      Current instruction register (CIR)
      Holds the instruction being decoded and executed.
      Accumulator (ACC)
      Holds the results of ALU calculations.

      The fetch–decode–execute cycle repeats millions of times a second:

      1. Fetch: the PC gives the address of the next instruction; the instruction is copied from memory into the MDR, then into the CIR; the PC increases by one.
      2. Decode: the control unit works out what the instruction means.
      3. Execute: the instruction is carried out — by the ALU, or by reading or writing data.

      What makes a CPU faster?

      • Clock speed — more cycles per second (measured in GHz) means more instructions per second. A faster clock also uses more power and makes more heat.
      • Number of cores — more cores can run more instructions at the same time. This helps most when the software can split its work across cores.
      • Cache size — a larger cache keeps more instructions and data close to the CPU, so it waits less for main memory.
      • More RAM helps when a program's data does not fit in memory, but it does not make the CPU itself faster.

      4.3Logic gates and truth tables

      A logic gate takes binary inputs (1 = true / on, 0 = false / off) and gives one output. NOT has one input; every other gate you need has two. Try each one:

      Try it: gate playground

      Switch A and B on and off. Each gate shows its output. NOT uses only A.

      GateRuleBoolean form
      NOTOutput is the opposite of the inputX = NOT A
      ANDOutput 1 only when both inputs are 1X = A AND B
      OROutput 1 when at least one input is 1X = A OR B
      NANDNOT AND: the opposite of ANDX = NOT (A AND B)
      NORNOT OR: the opposite of ORX = NOT (A OR B)
      XOROutput 1 when the inputs are differentX = A XOR B

      Truth tables

      ABANDORNANDNORXOR
      0000110
      0101101
      1001101
      1111000

      Circuits join gates so the output of one is the input of another. Work from the inputs towards the output, and add one column for every gate. With n inputs a truth table has 2n rows (two inputs: 4 rows; three inputs: 8 rows). List the input rows in binary counting order.

      Try it: truth table builder

      Choose an expression. The table shows the working column for each gate.

      Exam tip Fill the truth table one gate at a time and write the working column, even if the question does not ask for it. A wrong final answer can still earn marks for correct working columns. Check that the number of rows is 2n.

      4.4Operating systems and utility software

      The operating system (OS) is the software that manages the computer and lets the user and the programs use it. Its jobs include: managing memory, managing files, providing a user interface, managing hardware and peripherals (with drivers), security (user accounts and passwords), and multitasking (sharing the CPU between programs).

      Utility software does maintenance jobs: anti-virus software finds and removes malware; backup software copies files so they can be restored; defragmentation reorganises files on a hard drive so they load faster; compression software makes files smaller.

      4.5High-level and low-level languages

      Low-levelHigh-level
      ExamplesMachine code (binary), assembly languagePython, Java, C#
      Who it is forThe processorPeople — closer to English
      SpeedRuns fastest, no translation neededNeeds translating, so usually slower
      PortabilityWritten for one processor onlyCan run on many machines

      High-level code must be translated before the computer can run it. A compiler translates the whole program at once into machine code, which is then saved and run; an interpreter translates and runs it one line at a time, which is slower but easier for finding errors while you develop. Assembly language is translated by an assembler.

      Common mistakes
      • Saying ROM is "the same as" secondary storage — ROM is main memory that holds the boot program; a hard drive is secondary storage.
      • Mixing up the MAR and the MDR: the MAR holds the address, the MDR holds the data.
      • Forgetting that a compiler translates the whole program before it runs, while an interpreter translates line by line as it runs.

      1. Fetch: the instruction is copied from memory (address in the PC) into the MDR and then the CIR, and the PC increases by one. Decode: the control unit works out what the instruction means. Execute: the instruction is carried out by the ALU or by reading/writing data.
      2. Any two of: add more cores so more instructions run at the same time; increase the cache size so the CPU waits less for memory; add more RAM so programs do not need to use slow secondary storage while running. (Increasing clock speed further would also help but was already done in the question.)
      3. Three inputs → 8 rows. Work out the A AND B column, then the NOT C column, then OR them: X = 1 except when A AND B = 0 and C = 1. Rows (A B C → X): 000→1, 001→0, 010→1, 011→0, 100→1, 101→0, 110→1, 111→1.
      4. Operating system: any two of managing memory, managing files, providing a user interface, managing hardware/peripherals, security, multitasking. Utility software: any two of anti-virus, backup, defragmentation, compression.

      5

      Communication and the Internet

      How computers talk to each other: networks, the hardware that connects them, the protocols that agree the rules, and how to keep a network safe.

      5.1Networks

      A network is two or more computers connected so they can share data and resources, such as printers and files.

      LAN (Local Area Network)WAN (Wide Area Network)
      SizeOne building or site (a school, an office)Across cities or countries — the internet is the largest WAN
      SpeedFastSlower (long distances, many routers)
      Who owns itOne organisationMany owners, linked together

      Network hardware: a network interface card (NIC) connects a device to the network and gives it a unique MAC address; a router connects networks together and sends packets towards their destination; a switch connects devices inside a LAN and sends data only to the device it is for; a modem converts digital signals to analogue for a phone line (and back); a wireless access point (WAP) lets Wi-Fi devices join the network.

      Topologies

      Star
      Every device connects to a central switch. If one cable fails, only that device is affected; if the switch fails, the whole network stops. Most LANs use star.
      Bus
      All devices share one cable. Cheap, but a break in the cable stops the whole network, and only one device can send at a time.
      Mesh
      Devices connect to several others, so there is always another route if one fails. Very reliable, but expensive in cabling.

      Client–server and peer-to-peer

      In a client–server network, a server provides services (files, email, web pages) and clients request them — the server is powerful, centrally managed and backed up, but expensive. In a peer-to-peer network, devices share files directly with each other — cheap and simple, but harder to secure and back up, and a slow device slows everyone.

      5.2Protocols

      A protocol is a set of rules that devices agree to follow so they can communicate. Without agreed rules, one device's data would be meaningless to another.

      ProtocolWhat it does
      TCP/IPThe rules of the internet: TCP splits data into packets, numbers them and checks they arrive; IP addresses the packets and routes them.
      HTTP / HTTPSTransfers web pages. HTTPS adds encryption (SSL/TLS), so passwords and card details cannot be read on the way.
      FTPTransfers files between computers.
      SMTPSends email from a client to a mail server, and between mail servers.
      DNSTurns a domain name (www.wailinhtet.com) into an IP address the computer can use.

      An IP address identifies a device on a network (and can change). A MAC address is built into the network card and never changes. Data travels in packets, each with a header (sender and destination addresses, packet number) and a payload; routers read the header and choose the best route at that moment.

      5.3Network security

      Threats to a network:

      • Malware — viruses, worms, spyware and ransomware that damage, steal or lock data.
      • Phishing — fake emails or websites that trick people into giving away passwords.
      • Hacking — unauthorised access, often through weak passwords or unpatched software.
      • Denial of service (DoS) — flooding a server with requests so real users cannot get in.

      Defences:

      • Firewall — software or hardware that checks traffic in and out of the network and blocks anything that breaks its rules.
      • Strong passwords and user access levels — each user can only reach what they need; accounts are locked after too many wrong tries.
      • Encryption — data is scrambled so it is useless if intercepted (HTTPS, encrypted Wi-Fi).
      • Anti-malware software and updates — scans files and patches the holes attackers use.
      • Proxy server — sits between users and the internet, filtering requests and hiding the internal network.
      Exam tip When a question asks for "one threat and one way to protect against it", match them: phishing → train users and check the sender's address; malware → anti-malware software and updates; hacking → strong passwords and two-factor authentication. A defence that does not match the threat earns no marks.

      6

      The Bigger Picture

      What computing means for people and the planet: ethical questions, the law, and the environment.

      6.1Ethical issues

      Technology brings benefits, but it also creates questions with no simple answer. In the exam, you are usually asked to discuss both sides of an issue, not to pick one.

      Privacy
      Companies and governments collect huge amounts of personal data. People gain convenience (personalised services, safety) but lose control over who knows what about them. CCTV, location tracking and social media posts can all be used in ways the person did not expect.
      Surveillance
      Cameras, phone tracking and workplace monitoring can make places safer and workplaces fairer — but they can also be used to watch people without good reason, and data collected for one purpose can be used for another.
      AI and bias
      AI systems learn from data. If the data is biased, the system makes unfair decisions — for example, a hiring system trained on past data may favour one group of applicants. Someone must be responsible when an AI system gets it wrong.
      Digital divide
      Not everyone has the same access to computers and the internet. People without access are left behind in education, work and services that move online.
      Social media and health
      Social media connects people and spreads information quickly, but it can also spread false information, encourage addiction and harm mental health, especially for young people.

      6.2Legal issues

      Laws set the rules for how computers and data may be used. The main laws you need to know:

      LawWhat it covers
      Data Protection Act 2018 (UK, with GDPR)Personal data must be collected fairly and lawfully, kept secure, kept no longer than needed, and not shared without a lawful reason. People have the right to see their own data and ask for it to be corrected or deleted.
      Computer Misuse Act 1990It is a crime to access a computer system without permission, to access it with intent to commit a further crime, or to change or delete data without permission. Hacking and writing malware are offences.
      Copyright, Designs and Patents Act 1988Creative work (software, music, films, images, text) belongs to its creator. Copying, sharing or using it without permission — including pirated software and music — is illegal.

      Other legal points: software is usually licensed, not sold — the licence says how many computers may use it and what you may do with it. Open-source software can be used and changed freely under its licence, but the licence terms still apply.

      6.3Environmental issues

      • E-waste: old phones and computers contain toxic materials (lead, mercury) and valuable metals. Thrown away carelessly, they poison soil and water; recycled properly, the metals can be recovered.
      • Energy use: data centres, networks and devices use large amounts of electricity. Streaming video and training large AI models use far more energy than most people realise.
      • Manufacturing: making a device uses raw materials, water and energy, and creates waste — so a phone's environmental cost starts before it is ever switched on.
      • Planned obsolescence: devices are designed to be replaced rather than repaired, which increases waste. Repairing, reusing and recycling reduce the impact.
      Exam tip For "discuss" questions, give both sides: a benefit and a drawback, each with a reason. Then finish with a balanced judgement — for example, "on balance, the benefit is greater when the data is protected by law and the user gives informed consent". A one-sided answer cannot reach the top marks.

      These are practice questions written for this course — they are not from a real past paper.

      1. Discuss the ethical issues of a school using CCTV cameras in classrooms. Give one argument for and one against. [4]
      2. Explain how the Data Protection Act protects a person's data. Give two rules the Act sets. [4]
      3. A student downloads a pirated copy of a program instead of buying it. Which law is broken, and what is one consequence? [2]
      4. Describe two environmental problems caused by old computers and phones, and one way each problem can be reduced. [4]
      Model answers

      2. Personal data must be collected fairly and lawfully and kept secure; it must not be kept longer than needed; people have the right to see their data and ask for it to be corrected or deleted.
      3. The Copyright, Designs and Patents Act 1988 is broken. Consequences include a fine, and the pirated copy may contain malware.
      4. Toxic materials (lead, mercury) can poison soil and water if dumped — reduce by recycling e-waste through proper schemes. Making new devices uses raw materials and energy — reduce by repairing and reusing devices instead of replacing them.

      Paper 2 tasks give you a description in words. Before you type any code, plan it in three lines:

      P1.2Errors: finding and fixing them

      Error typeWhat happensExample
      Syntax errorThe program will not run. Python shows an error message and the line number.if age > 18 (missing colon)
      Runtime errorThe program starts, then crashes. The error message names the line and the problem.print(10 / 0) (division by zero)

      P1.3Testing

      Choose test data that covers the three cases examiners look for:

      Normal data
      Ordinary values the program should accept, e.g. a mark of 75.
      Boundary data
      Values at the edge of what is allowed, e.g. a mark of 0 and a mark of 100 — where programs most often go wrong.
      Erroneous data
      Values the program should reject, e.g. a mark of −5 or 101 — the program should handle them, not crash.

      Write a small test table: test data, expected result, actual result, pass or fail. If the actual result differs, that is where the bug is.

      P1.4Reading and writing text files

      Paper 2 tasks often give you a file to read and ask you to write results to a file. The pattern is always the same:

        names.append(line.strip())

      P2

      Algorithms in Code

      Turning the standard algorithms into Python: linear and binary search, bubble sort and merge sort — and modifying starter code, which is how Paper 2 usually asks for them.

      P2.1Linear and binary search in Python

      def linear_search(items, target):
    for i in range(len(items)):
        if items[i] == target:
            return i
    return -1

names = ["Aung", "Htar", "May", "Zaw"]
print(linear_search(names, "May"))   # 2
print(linear_search(names, "Ko"))    # -1 (not found)
      def binary_search(items, target):   # items MUST be sorted
    low = 0
    high = len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

      The binary search needs low <= high, not low < high — with < alone, a list with one item left is never checked. Returning -1 for "not found" is the standard choice, because −1 can never be a real index.

      P2.2Bubble sort and merge sort in Python

      def bubble_sort(items):
    n = len(items)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if items[j] > items[j + 1]:
                items[j], items[j + 1] = items[j + 1], items[j]
                swapped = True
        if not swapped:
            break
    return items

      The swapped flag is the early stop: if a whole pass makes no swaps, the list is already sorted and the sort can finish. Without it, the sort still works — it just does wasted passes.

      def merge_sort(items):
    if len(items) <= 1:
        return items
    mid = len(items) // 2
    left = merge_sort(items[:mid])
    right = merge_sort(items[mid:])
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result += left[i:] + right[j:]
    return result

      P2.3Modifying starter code

      Paper 2 often gives you starter code and asks you to change it. Read the starter code first and work out what each part does before you change anything. Common changes: add a new condition, change a loop, add a count, or store results in a list.

      Worked example — starter code prints the numbers 1 to 10. Task: change it so it prints only the even numbers, and counts how many there are.

      # Starter code

    print(i)

# Modified code

    if i % 2 == 0:
        print(i)
        count = count + 1
print("Even numbers:", count)
      Common mistakes
      • Changing the starter code before reading it — you may break a part that already worked.
      • Forgetting to reset a counter (like count = 0) before the loop.
      • Using range(1, 10) when you need 1 to 10 — range stops one short.

      P3

      Pseudocode and Trace Tables

      Paper 2 gives you a pseudocode reference sheet. This section teaches you to read it, write it, and follow it with a trace table — the skill that turns a confusing program into marks.

      P3.1Reading pseudocode

      Pseudocode is not a programming language — it is a way of writing an algorithm so a person can read it. The exam gives you a reference sheet with the exact words it uses. The ones you will meet most often:

      PseudocodeMeaningPython
      DECLARE X : INTEGERCreate a variable called Xx = 0
      X ← 5Give X the value 5x = 5
      INPUT XRead a value into Xx = input()
      OUTPUT XShow the value of Xprint(x)
      IF … THEN … ELSE … ENDIFChoose a pathif … else:
      FOR i ← 1 TO 5Repeat 5 timesfor i in range(1, 6):
      WHILE … DO … ENDWHILERepeat while truewhile …:
      REPEAT … UNTIL …Repeat at least once, until truewhile True: … if …: break
      LENGTH(Text)Number of characterslen(text)
      SUBSTRING(Text, 1, 3)Characters 1 to 3text[0:3]

      Read pseudocode the same way you read Python: line by line, top to bottom, following the branches and loops. The only real differences are the words (← instead of =, ENDIF instead of indentation) and the fact that array indexes start at 1 in pseudocode but at 0 in Python.

      P3.2Trace tables

      A trace table follows a program one line at a time and writes down the value of every variable after each step. It is the best way to find the output of a program — and to find a logic error.

      Worked example:

      Total ← 0
FOR Count ← 1 TO 3
    INPUT Number
    Total ← Total + Number
NEXT Count
OUTPUT Total

      Inputs: 4, 7, 2.

      TotalCountNumberOutput
      0–––
      014–
      414–
      427–
      1127–
      1132–
      1332–
      133213

      Rules for a good trace table: one column per variable (and one for the output); one row per step, not per line of code; write the value only when it changes; never skip the first row, which shows the starting values.

      P3.3Validation and verification

      Before data is processed, check it. Validation is done by the program: a range check (is a mark between 0 and 100?), a presence check (is the field empty?), a type check (is it a number?), a length check (is the password at least 8 characters?). If the data fails, the program asks again instead of crashing or storing bad data.

      Verification is done by the person: checking the data was entered correctly — typing it twice and comparing, or reading it back on screen and confirming. Validation checks the data is reasonable; verification checks it is correct.

      Exam tip In a trace table, the most common mistake is writing the new value of a variable in the wrong row — for example, writing the new Total before the INPUT line has run. Follow the lines in order, and change a value only when the line that changes it has run.

      P4.1How the Paper 2 exam works

      Paper 2 is a 3-hour practical exam on a computer (80 marks, 50% of the qualification). It is a supervised session: you work on the machine, using Python (the other approved languages are C# and Java, but this course teaches Python). The exam has two parts: written questions (short answers about code, algorithms and data) and practical tasks (writing and changing programs on the computer). A pseudocode reference sheet is given to you in the exam, so you do not need to memorise the pseudocode words.

      You may be given starter code or data files to work with. Your work is saved and marked afterwards — so save often, and make sure your final program is the one you want marked.

      P4.2A time plan for 3 hours

      TimeWhat to do
      0:00 – 0:15Read the whole paper. Note the written questions and the practical tasks, and how many marks each is worth.

      0:45 – 2:30Work through the practical tasks in order. Read each task fully, plan (input–process–output), then code and test.

      P4.3Full worked exam-style task

      Task: A club keeps its members' names and ages in a file called members.txt (one member per line, name then age, separated by a comma). Write a program that:

      1. Reads all the members from the file.
      2. Counts how many members are under 18.
      3. Writes the names of the under-18 members to a file called juniors.txt.
      4. Prints the number of junior members.
      juniors = []
count = 0
with open("members.txt") as f:
    for line in f:
        parts = line.strip().split(",")
        name = parts[0]
        age = int(parts[1])
        if age < 18:
            juniors.append(name)
            count = count + 1

with open("juniors.txt", "w") as f:
    for name in juniors:
        f.write(name + "\n")

print("Junior members:", count)

      What the examiner is looking for: reading the file line by line, splitting each line on the comma, casting the age to an integer, the condition age < 18, writing the names to the output file, and printing the count. A program that does all of these, even with a small slip in one line, earns most of the marks.

      Common mistakes
      • Forgetting to strip the newline, so the age has a hidden character and the cast fails.
      • Forgetting to cast the age to an integer, so age < 18 compares text with a number and crashes.
      • Writing the output file but never closing it or never saving the program — the marker only sees what is saved.
      • Spending the whole exam on one hard task and leaving easy marks unanswered.
